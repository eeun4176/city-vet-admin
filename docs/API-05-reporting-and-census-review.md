# Reporting workflows and census review

> **Status (2026-10-27): historical record.** Written before e-Vet Field (Salin) was connected on 2026-10-24. Roles, names, stubs and sign-in have changed since; see [what changed](README.md#what-changed-since-the-phase-records-below). Where this differs from the code, the code is right.

This document describes the live planning gate, temporary report basket, Spay and Neuter workbook workflow, and reversible census review in `Modules/local-test-copy`. The API role checks remain authoritative; the workbook and status controls are available to `Admin` (including accounts migrated from the legacy Encoder role) and `SuperAdmin`.

## Paravet record and sign-in creation

Creating a Paravet from the **Paravets** page now creates the directory entry
and its login-enabled `Paravet` account in one database transaction. The
account key is generated by the account-key trigger and a 15-minute,
one-time temporary password is issued through the existing credential
function. The API response returns both values for immediate handoff; the
temporary password is not saved in the directory record and is not available
again after the creation response. If the account or directory entry cannot
be created, the transaction rolls back both.

The create action accepts one Paravet per request so the credential pair can
be displayed once:

| Method & path | Who | Contract |
|---|---|---|
| `POST /records/paravets?createAccount=true` | Admin, SuperAdmin | `{records:[{firstName,middleName?,lastName,suffix?,mobile,barangay}]}`. Creates the directory record and portal account atomically; returns the record, generated `accountKey`, one-time `temporaryPassword`, and 15-minute expiry. Duplicate active accounts for the same name and barangay are rejected. |

## Planning estimates

Planning baselines use active, completed, validly dated live service rows in the caller's existing barangay scope and selected year. The UI withholds estimate values until there are at least **10 dated live service records spanning at least 3 distinct calendar months**. Sample records never satisfy this gate. The baseline averages the most recent three observed months. Spay/neuter rows imported from the workbook count as one service record for sample sufficiency; their reported procedure quantities are summed for service-volume trend and planning measures.

## Temporary report basket

The working Report basket is per account and browser session (`sessionStorage`). Admin and SuperAdmin may save private account-owned drafts using `/report-workspace`, with version checks on updates. Records and analytical blocks are revalidated at preview/export; saved values do not grant access. See [redesign implementation](./REDESIGN-IMPLEMENTATION.md) for the four-stage decision reports and selectable outputs. Users add selected rows from records, accounts, census submissions, and analytics evidence, then choose which safe fields to include. Current list/API permissions remain the source of truth; basket state does not grant access to additional records. The print preview uses the shared City Veterinary Office letterhead.

## Spay and Neuter Monthly Report

| Method & path | Who | Contract |
|---|---|---|
| `GET /spay-neuter-report?mode=template` | Admin, SuperAdmin | Returns a base64-encoded `.xlsx` template (`filename`, `data`) with the City Veterinary Office logo, eight required headers on row 7, month sections, and formula-only totals. |
| `GET /spay-neuter-report?mode=export&year=2026&month=1&barangay=Muzon%20Proper` | Admin, SuperAdmin | Returns a populated, logo-branded `.xlsx` workbook of matching imported live records, grouped by month with recalculated totals. `year` defaults to the current year; `month` and `barangay` are optional. Exports are capped at 2,000 records; narrow the period or barangay if the cap is exceeded. |
| `POST /spay-neuter-report` | Admin, SuperAdmin | JSON `{mode:"preview"|"import",filename,data}` where `data` is base64 workbook bytes. Preview returns row count, months, total procedures, up to 100 preview rows, validation errors, and whether the exact file was already imported. Import accepts only error-free, non-empty workbooks. |
| `POST /records/services/undo-import` | Importing Admin, SuperAdmin | `{batchId}`. Uses the existing conflict-guarded import undo; if an imported service has changed, no rows are removed and the report must be resolved manually. |

The workbook has one record per dated service row, arranged under the corresponding month section. Its exact headers are:

1. `Date`
2. `Name of Client`
3. `Barangay`
4. `No. Castrated Canine (Male)`
5. `No. Spayed Canine (Female)`
6. `No. Castrated Feline (Male)`
7. `No. Spayed Feline (Female)`
8. `Remarks`

Dates must be real Excel dates or `YYYY-MM-DD`, must match their month section, and must be valid calendar dates. Client and barangay are required; barangay must exactly match an active system barangay. Counts are whole non-negative numbers and at least one procedure is required per row. Formula totals are ignored, and formulas in data rows are rejected. Imports become completed `Kapon (Spay and Neuter)` records in the live `services` dataset. Each record retains all four counts, total procedures, client, barangay, date, remarks, and source. Exact workbook bytes cannot be imported twice until their prior import is undone.

## Census status history and safe approval undo/redo

| Method & path | Who | Contract |
|---|---|---|
| `GET /census/submissions/{id}/status` | Admin, SuperAdmin | Returns the current status, last 20 audited transitions, and guarded `canUndo`/`canRedo` flags with a reason when a change cannot safely be reversed. |
| `POST /census/submissions/{id}/status` | Admin, SuperAdmin | `{action:"set-status",status:"pending"|"approved"|"rejected",note?}`, `{action:"undo"}`, or `{action:"redo"}`. Rejection requires a reason of at least 3 characters. |

Every new approval snapshots the complete before/after owner and pet state affected by that submission inside the same transaction. Undo/redo compares current registry data to its expected snapshot before making any change; changes to affected owner or pet records block the operation rather than being overwritten. Update timestamps are ignored for conflict checks because database audit triggers refresh them during restoration. Status changes and review/undo/redo events are stored in `census_submission_status_history`. Existing approvals without snapshots are displayed as not safely undoable.

Each submission detail page (pending, approved, or rejected) includes traditional **Summary** and **Door-to-door** read-only tabs. The Summary tab follows the paper form's per-owner species/sex/classification/vaccination totals. Door-to-door shows submission metadata, owners, and pet-level details. The regular pending-review decisions remain available separately.

## Database migration

Apply `db/010_reporting_workflows.sql` after `db/009_notification_archive.sql` in each deployed database. The migration adds the import checksum, census snapshots, and status-history tables. Local test database setup applies it automatically. Do not edit historical migrations or apply schema changes directly to a live database outside the reviewed migration process.
